# 10-Week Self-Directed Semester

> **Modern C++ (3) + Systems Essentials (1) + ML / Deep Learning (3) + RL / Action Models / VLA (3) + FPS VLA Project (6) + Minimal Qwen3.5 Runtime Capstone (6)**  
> 핵심: **C++/Systems/Transformer는 minimal Qwen3.5 C++ runtime 프로젝트에, ML/RL/VLA는 FPS 환경의 vision-language-action agent 프로젝트에 직접 연결한다.**

---

## 1. 과목과 교재

| 트랙 | 주교재 / 자료 | 학기 목표 |
|---|---|---|
| Modern C++ | LearnCpp, cppreference | 문법 → pointer/reference/lifetime → RAII/move → STL → polymorphism/exception → 실전 코드 |
| Systems Essentials | OSTEP | process/API → virtual memory/paging/TLB → threads/locks/CV → profiling |

### 교재 범위 원칙

- LearnCpp는 **Ch.1~12, 17~20, 22 중심**으로 진행한다.
- 고급 TMP, 복잡한 inheritance hierarchy, 디자인 패턴 암기는 제외한다.
- OSTEP은 **Ch.4~6, 13~15, 18~20, 26~28, 30**만 본다.
- OSTEP Ch.7~9 Scheduling은 이번 학기에서 제외한다.
- filesystem, RAID, journaling, distributed systems는 제외한다.
- OS의 핵심 흐름은 **process → syscall/API → address space → paging/TLB → thread → lock/CV**다.
- CS231n은 **optimization/backprop, neural networks, CNN, training dynamics** 부분만 본다.
- CS224n은 **RNN/Seq2Seq는 연결고리**, 핵심은 **Attention / Transformer / language modeling**이다.
- Sutton & Barto는 **Ch.1, Ch.3, Ch.13 일부**를 본다.
- PPO는 작은 환경에서 직접 구현한다.
- GRPO는 PPO 이후 **toy 구현까지** 진행하되, LLM post-training 전체를 깊게 파지는 않는다.
- 프로젝트의 중심 학습 방식은 **Behavior Cloning → Action Chunking → Hierarchical VLA**다.
- ACT는 action chunking의 주자료로 사용한다.
- Diffusion Policy는 핵심 구조와 ACT와의 차이를 이해하는 정도로 제한한다.
- Modern Robotics는 이번 학기 독립 교재에서 제외한다.
- FPS 프로젝트에 필요한 coordinate/frame/vector 개념은 Unity 프로젝트에서 역학습한다.
- Qwen3.5 runtime 범위는 기존처럼 text backbone inference만 다룬다.

### 연계 규칙

- C++ pointer/reference/lifetime/RAII는 Qwen runtime의 tensor/weight/state ownership에 연결한다.
- OS는 **OSTEP Ch.4~6 → 13~15 → 18~20 → 26~28 → 30** 순서로만 본다.
- Scheduling Ch.7~9는 완전히 제외한다.
- Ch.18~20은 runtime의 memory behavior를 이해하기 위해 포함한다.
- ML은 CS231n의 NN/CNN 기반을 익힌 뒤 CS224n Attention/Transformer로 넘어간다.
- RNN/Seq2Seq는 Transformer의 등장 배경을 이해하는 수준에서 끝낸다.
- PPO는 RL의 기본 policy optimization을 이해하기 위해 직접 한 번 구현한다.
- GRPO는 PPO 이후 **advantage 계산 방식과 LLM/RL post-training 연결을 이해하기 위한 작은 구현**으로 제한한다.
- FPS VLA 프로젝트의 주 학습법은 RL이 아니라 imitation learning이다.
- 학습 순서는 **scripted expert → state BC → vision BC → vision-language BC → ACT/action chunk → hierarchical VLA**다.
- RL은 필요하면 이후 reward-based fine-tuning에 연결한다.
- FPS는 게임 완성 프로젝트가 아니라 VLA 연구환경이다.
- Qwen3.5 runtime은 기존 범위를 유지한다.

## 3. 두 프로젝트의 최소 범위

### A. FPS Vision-Language-Action Project (6학점)

```text
Unity greybox
→ scripted expert
→ state BC
→ visual BC
→ language-conditioned BC
→ ACT-style action chunk model
→ hierarchical VLA
→ unseen-layout evaluation
```

최소 task:

```text
GO_TO(target)
FOLLOW(target)
OBSERVE(target / direction)
HOLD(region)
REACH(region)
```

최소 action:

```text
move_x
move_y
look_x
look_y
```

필요 시 이후:

```text
stance
interaction
```

추가.

최소 model 비교:

```text
scripted baseline
→ state BC
→ vision BC
→ vision + language BC
→ ACT-style action chunk
→ hierarchical VLA
```

시간이 남으면 PPO policy를 navigation baseline으로 추가한다.

데이터:

- scripted expert trajectory
- start position randomization
- target randomization
- layout randomization
- command paraphrase/template 다양화
- observation/action sequence 저장

최소 metric:

- success rate
- completion time
- path efficiency
- collision rate
- action smoothness
- unseen-layout success
- unseen-command composition success
- inference latency

**성공 조건:** FPS 자체를 완성하는 게 아니라, **vision/language 조건을 받은 sequential action model을 만들고 BC → action chunk → hierarchy의 차이를 정량 비교**하면 성공.

