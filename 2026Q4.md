## C++ priorities

For robotics/simulator code, prioritize:
- references, pointers, const, value categories
- scope and object lifetime
- structs/classes and constructors
- RAII and ownership
- std::vector and containers
- iterators and generic algorithms
- inheritance / virtual functions
- templates at library-reading level
- headers, translation units, compiler/linker errors
- debugging with warnings, breakpoints, and call stack

The finish line is being able to read and modify robotics/C++ library code without syntax and ownership semantics constantly blocking you.

# 3. Machine Learning & Mathematical Foundations — 3 credits

## Main reference — one book only

**Kevin P. Murphy, _Probabilistic Machine Learning: An Introduction_ (2022)**

For this semester, this is the **only required ML textbook**.

Do not run a second mathematics textbook in parallel. The book itself contains the probability, statistics, information theory, linear algebra, matrix calculus, optimization, classical ML, neural-network, attention/Transformer, and PCA material needed for this course.

External material is allowed only as a quick lookup when a specific concept in PML is blocking progress. It is not a second syllabus.

PyTorch documentation is used only as an API reference once implementation begins.

## Why this ordering is different from the book order

The book introduces probability before its linear-algebra chapter. For this course, the reading order is intentionally rearranged around the gaps found in the diagnostic:

1. linear algebra and matrix calculus,
2. probability and statistics,
3. information theory and optimization,
4. PCA and probabilistic interpretations of familiar ML,
5. neural networks,
6. attention and Transformers.

You already know enough introductory supervised-learning vocabulary that **Ch.1 does not need a full week**.

## What is deliberately skipped or compressed

PML is broad enough that trying to finish the whole book in one semester would destroy the point of the course.

The following are useful but **not core for this 16-week robot-learning track**:

- Ch.9 LDA / Naive Bayes — skim only if curious
- Ch.12 Generalized Linear Models — optional
- Ch.14 CNNs — later when the robotics project starts using vision
- Ch.16 KNN / exemplar methods — optional
- Ch.17 kernel methods / SVM / Gaussian processes — later
- Ch.18 trees / random forests / boosting — know they exist, no full-week allocation
- Ch.19 semi/self-supervised/meta-learning — later
- Ch.20.2+ factor analysis / autoencoders / manifold learning — optional after PCA
- Ch.21 clustering — optional
- Ch.22–23 recommender systems / graph embeddings — not needed now

## ML practical sequence

### Weeks 1–3 — NumPy linear algebra
Implement small experiments for:

- matrix multiplication and linear transformations
- basis / rank
- projection
- EVD and SVD
- least-squares solution
- numerical vs analytic derivatives

### Weeks 4–8 — Probability / statistics
Implement:

- sampling Bernoulli / categorical / Gaussian variables
- empirical expectation and variance
- covariance matrices
- conditional probability / Bayes toy examples
- Bernoulli and Gaussian MLE
- MAP with a simple prior
- entropy / cross-entropy / KL calculations

### Weeks 9–11 — Optimization / PCA / probabilistic ML
Implement:

- gradient descent and SGD
- PCA from centered data
- compare EVD and SVD PCA
- logistic regression from equations
- linear regression as Gaussian MLE

### Weeks 12–14 — neural networks / PyTorch
First understand the equations in Ch.13, then use PyTorch:

- forward pass
- loss
- autograd / backprop
- optimizer update
- minibatch training
- initialization / regularization

Do **not** start the semester by grinding through the PyTorch beginner tutorial.

### Weeks 15–16 — attention
Use PML Ch.15 as the textbook explanation, then read the original Transformer paper as the final application.

The target is to understand:

- why \(QK^\top\) measures compatibility
- why softmax produces attention weights
- why the score is scaled by \(\sqrt{d_k}\)
- how the weights combine \(V\)
- why multiple heads help
- how positional information enters a non-recurrent model

## RL coding progression

- Weeks 1–6: tiny NumPy/Gymnasium examples if useful
- Weeks 8–12: small PyTorch policy/value networks
- Weeks 13–16: read and modify RSL-RL PPO configs rather than reimplementing an entire production PPO stack

## RL endpoint

You should be able to answer:

- Why do we need \(V\) and \(Q\)?
- What is bootstrapping?
- Why does actor-critic use a critic?
- What is an advantage?
- Why does PPO use a probability ratio?
- What exactly does clipping prevent?
- What data are collected during a rollout?
- Which parts of RSL-RL correspond to the equations?

## Isaac Lab concepts to know by Week 11

### Environment structure

`EnvCfg` is configuration/design.

`Env` is runtime behavior.

For a Direct environment, understand the purpose of:

```text
_setup_scene()
_pre_physics_step(actions)
_apply_action()
_get_observations()
_get_rewards()
_get_dones()
_reset_idx(env_ids)
```

### Simulation timing

Understand:

- physics `dt`
- `decimation`
- policy/control frequency
- render frequency

### Batched simulation

Understand that:

```text
robot.data.*
```

contains tensors for many environments at once.

The policy receives a batch of observations and emits a batch of actions.

### Actions

For the gimbal, deliberately choose one control interface:

- torque target, or
- velocity target, or
- position target

Do not switch interfaces casually while debugging the task.

### Observations

Start small:

- orientation error
- angular velocity
- joint position/velocity if needed
- previous action if useful

Only add more observations when there is a reason.

### Reward

Start interpretable:

```text
- orientation error
- angular velocity penalty
- action magnitude / action-change penalty
```

Then add complexity only after the baseline trains.

# End-of-semester target

At the end of 16 weeks, the target is not “master all of CS/ML/robotics.”

You should be able to:

1. read ordinary C++ robotics code without ownership/lifetime syntax constantly blocking you;
2. understand what the OS is doing underneath processes, memory, threads, syscalls, and files;
3. understand the probability/linear-algebra/calculus notation used in modern ML papers;
4. read the core Transformer attention equations without treating them as magic;
5. derive the conceptual path from MDPs to PPO;
6. build a custom Isaac Lab Direct RL environment;
7. train and evaluate a gimbal stabilization policy and compare it against a classical feedback controller.

That is the semester's finish line.
