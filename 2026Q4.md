# 16-Week Self-Directed Semester — Full Curriculum

## Semester structure

| Course | Credits | Main goal |
|---|---:|---|
| C++ | 3 | Write and debug nontrivial modern C++ programs; understand memory, RAII, STL, move semantics, templates |
| Operating Systems | 3 | Understand processes, virtual memory, concurrency, file systems, and system calls |
| Machine Learning & Mathematical Foundations | 3 | Fill probability/linear-algebra gaps and reach paper-reading-level ML foundations |
| Reinforcement Learning | 3 | Understand MDP → value methods → function approximation → policy gradients → PPO |
| Robotics / Isaac Lab | 6 | Build and train a custom robot-control environment, ending in a gimbal PPO project |
| **Total** | **18** | |

The courses are meant to run **in parallel**, not sequentially.

# 1. C++ — 3 credits

## Main reference

**C++ Primer, 5th Edition — Lippman, Lajoie, Moo**

Supplement:
- CMake official tutorial
- compiler warnings / GDB / AddressSanitizer as practical tooling

The goal is not to finish every page of *C++ Primer*. Read the listed chapters/sections and write code every week.

# 3. Machine Learning & Mathematical Foundations — 3 credits

## Why this course is arranged this way

You already have useful intuition for:

- supervised vs unsupervised learning
- regression vs classification
- train / validation / test
- overfitting / underfitting
- parameter vs hyperparameter
- basic gradient descent
- precision / recall / confusion matrix
- basic neural-network / chain-rule intuition

The main holes are lower-level mathematical connections:

- probability density vs probability
- random variables / expectation / covariance
- likelihood / MLE / MAP
- information theory
- vector spaces / projection / SVD / PCA
- vector calculus and optimization

So this course does **not** waste the first month re-teaching generic introductory ML.

## Main references

### Mathematics for Machine Learning — Deisenroth, Faisal, Ong
- **Ch.2 Linear Algebra**
- **Ch.3 Analytic Geometry**
- **Ch.4 Matrix Decompositions**
- **Ch.5 Vector Calculus**
- **Ch.6 Probability and Distributions**
- **Ch.7 Continuous Optimization**
- **Ch.9 Linear Regression**
- **Ch.10 Dimensionality Reduction with Principal Component Analysis**

## ML practical sequence

- NumPy matrix/projection exercises
- eigendecomposition and SVD experiments
- sampling / expectation / variance / covariance
- Gaussian likelihood / MLE
- entropy / KL calculations
- PCA from scratch

Only from Week 13 onward should PyTorch become the normal implementation layer.

# 4. Reinforcement Learning — 3 credits

## Main reference

**Reinforcement Learning: An Introduction, 2nd Edition — Sutton & Barto**

Later:
- **Schulman et al., Proximal Policy Optimization Algorithms**
- selected material on **Generalized Advantage Estimation (GAE)**

The point is not to master every tabular algorithm. The sequence exists so PPO does not remain a black box.

## Weekly curriculum

| Week | Reading | Topics / output |
|---|---|---|
| **1** | Sutton & Barto **Ch.1 Introduction** | agent/environment loop, reward, return, policy, episodic vs continuing |
| **2** | **Ch.3 Finite Markov Decision Processes** | states/actions, transition dynamics, Markov property, discounted return |
| **3** | **Ch.3** | state-value \(V\), action-value \(Q\), Bellman expectation equations |
| **4** | **Ch.4 Dynamic Programming** | policy evaluation, policy improvement, generalized policy iteration |

| **6** | **Ch.6 Temporal-Difference Learning** | bootstrapping, TD(0), SARSA, Q-learning |
| **7** | selected **Ch.7 n-step Bootstrapping** | bias/variance trade-off in returns; n-step targets |
| **8** | **Ch.9 On-policy Prediction with Approximation** | feature/function approximation; SGD update viewpoint |
| **9** | **Ch.10 On-policy Control with Approximation** | approximate control, continuous/large state spaces |
| **10** | selected **Ch.11 Off-policy Methods with Approximation** | why function approximation + bootstrapping + off-policy can be unstable |
| **11** | **Ch.13 Policy Gradient Methods** | parameterized policy, objective, REINFORCE |
| **12** | **Ch.13** | baseline, actor-critic intuition, advantage |

## RL coding progression

- Weeks 1–6: tiny NumPy/Gymnasium examples if useful
- Weeks 8–12: small PyTorch policy/value networks
- Weeks 13–16: read and modify RSL-RL PPO configs rather than reimplementing an entire production PPO stack

## RL endpoint

You should be able to answer:

- Why do we need \(V\) and \(Q\)?
- What is bootstrapping?
- Why does actor-critic use a critic?
- What is an advantage?
- Why does PPO use a probability ratio?
- What exactly does clipping prevent?
- What data are collected during a rollout?
- Which parts of RSL-RL correspond to the equations?

## Isaac Lab concepts to know by Week 11

### Environment structure

`EnvCfg` is configuration/design.

`Env` is runtime behavior.

For a Direct environment, understand the purpose of:

```text
_setup_scene()
_pre_physics_step(actions)
_apply_action()
_get_observations()
_get_rewards()
_get_dones()
_reset_idx(env_ids)
```

### Simulation timing

Understand:

- physics `dt`
- `decimation`
- policy/control frequency
- render frequency

### Batched simulation

Understand that:

```text
robot.data.*
```

contains tensors for many environments at once.

The policy receives a batch of observations and emits a batch of actions.

### Actions

For the gimbal, deliberately choose one control interface:

- torque target, or
- velocity target, or
- position target

Do not switch interfaces casually while debugging the task.

### Observations

Start small:

- orientation error
- angular velocity
- joint position/velocity if needed
- previous action if useful

Only add more observations when there is a reason.

### Reward

Start interpretable:

```text
- orientation error
- angular velocity penalty
- action magnitude / action-change penalty
```

Then add complexity only after the baseline trains.

# End-of-semester target

At the end of 16 weeks, the target is not “master all of CS/ML/robotics.”

You should be able to:

1. read ordinary C++ robotics code without ownership/lifetime syntax constantly blocking you;
2. understand what the OS is doing underneath processes, memory, threads, syscalls, and files;
3. understand the probability/linear-algebra/calculus notation used in modern ML papers;
4. read the core Transformer attention equations without treating them as magic;
5. derive the conceptual path from MDPs to PPO;
6. build a custom Isaac Lab Direct RL environment;
7. train and evaluate a gimbal stabilization policy and compare it against a classical feedback controller.

That is the semester's finish line.
