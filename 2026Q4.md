### 교재 범위 원칙

- LearnCpp는 **필수 장 중심**으로 진행한다. pointer/reference/lifetime/RAII/move/STL을 우선하고, polymorphism과 exception 기본까지 학습한다.
- 복잡한 inheritance hierarchy, template metaprogramming, 디자인 패턴 암기는 후순위다.
- OSTEP은 **Process / Scheduling / Virtual Memory / Concurrency**를 우선한다.
- ML은 고전 ML 전체를 훑기보다 **NN → sequence model → attention → Transformer**로 이어지는 흐름을 우선한다.
- PCA/SVM은 representation / margin / feature space의 의미를 이해하는 수준으로만 본다.
- RNN/LSTM/Seq2Seq는 직접 깊게 구현하지 않고 **Transformer가 왜 등장했는지 이해하는 연결고리**로 본다.
- RL은 MDP/TD/policy gradient를 학습하고 **작은 PPO를 직접 구현**하되, 로보틱스 프로젝트 자체를 PPO 중심으로 만들지는 않는다.
- Modern Robotics는 전통 로봇공학 전체를 완독하지 않는다. rigid transform / joint / DOF / FK / Jacobian의 의미까지를 핵심으로 한다.
- Isaac은 RL 튜토리얼 완료보다 **control → demonstration → imitation → action model** 흐름을 직접 구성하는 것을 우선한다.
- LLM 프로젝트는 기존 `llama2.c`를 최적화하는 것보다 **작은 inference runtime을 이해한 뒤 Qwen3.5 text architecture를 직접 지원하는 것**을 핵심 목표로 한다.
- Qwen3.5 프로젝트에서 vision encoder, MTP, full tokenizer 구현은 필수가 아니다. 먼저 **text backbone correctness**를 확보한다.

### 연계 규칙

- C++ pointer/array/lifetime/RAII 학습은 Qwen3.5 runtime의 weight/tensor/state ownership에 바로 적용한다.
- OS VM/thread/profiling은 runtime의 model loading, memory footprint, threading, inference 성능 분석에 연결한다.
- ML은 NN → RNN/LSTM/Seq2Seq → Attention → Transformer 순서로 진행하되, 이전 구조는 현대 모델 이해에 필요한 만큼만 학습한다.
- RL은 MDP/TD/PPO를 직접 한 번 구현해 보는 수준까지 진행하지만, Isaac 프로젝트의 최종 목표는 PPO가 아니라 **imitation/action model**이다.
- 로보틱스는 수식 완독보다 **robot state와 action model output이 실제 joint/control로 어떻게 연결되는지**를 이해하는 데 초점을 둔다.
