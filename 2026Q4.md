# 10-Week Self-Directed Semester

> **Modern C++ (3) + Operating Systems (3) + Machine Learning / Deep Learning (3) + Robot Learning (3) + Isaac Lab Robotics Project (6) + Minimal Qwen3.5 Runtime Capstone (6)**  
> 핵심: **C++/OS/ML은 minimal Qwen3.5 C++ runtime 프로젝트에, ML/RL/Isaac은 action model 기반 로보틱스 프로젝트에 직접 연결한다.**

### 교재 범위 원칙

- LearnCpp는 **필수 장 중심**으로 진행한다. pointer/reference/lifetime/RAII/move/STL을 우선하고, polymorphism과 exception 기본까지 학습한다.
- 복잡한 inheritance hierarchy, template metaprogramming, 디자인 패턴 암기는 후순위다.
- OSTEP은 **Process / Scheduling / Virtual Memory / Concurrency**를 우선한다.
- ML은 고전 ML 전체를 훑기보다 **NN → sequence model → attention → Transformer**로 이어지는 흐름을 우선한다.
- PCA/SVM은 representation / margin / feature space의 의미를 이해하는 수준으로만 본다.
- RNN/LSTM/Seq2Seq는 직접 깊게 구현하지 않고 **Transformer가 왜 등장했는지 이해하는 연결고리**로 본다.
- Transformer는 이론만 읽고 넘어가지 않고 **NumPy로 작은 decoder-only inference를 직접 구현**한다.
- NumPy scratch에서는 training/backprop/optimizer/tokenizer 학습까지 구현하지 않는다. **forward / autoregressive inference / KV cache 이해가 목표**다.
- RL은 MDP/TD/policy gradient를 학습하고 **작은 PPO를 직접 구현**하되, 로보틱스 프로젝트 자체를 PPO 중심으로 만들지는 않는다.
- Modern Robotics는 전통 로봇공학 전체를 완독하지 않는다. rigid transform / joint / DOF / FK / Jacobian의 의미까지를 핵심으로 한다.
- Isaac은 RL 튜토리얼 완료보다 **control → demonstration → imitation → action model** 흐름을 직접 구성하는 것을 우선한다.
- LLM 프로젝트는 **Transformer를 먼저 NumPy로 직접 구현한 뒤** `llama2.c`를 읽고, 그 다음 Qwen3.5 runtime을 구현한다.
- NumPy 단계에서는 single-head attention → multi-head decoder block → autoregressive generation → KV cache 순서로 구현한다.
- NumPy scratch의 목적은 training이 아니라 **Transformer inference의 수식, tensor shape, dataflow를 코드로 이해하는 것**이다. backward / optimizer / tokenizer 학습은 구현하지 않는다.
- `llama2.c`는 Transformer를 처음 배우기 위한 코드가 아니라, NumPy에서 이해한 구조가 low-level C에서 어떻게 구현되는지 확인하는 reference implementation으로 사용한다.
- Qwen3.5 포팅은 `llama2.c`의 inference path까지 이해한 뒤 시작한다. vanilla decoder와의 차이를 하나씩 추가한다.
- Qwen3.5 프로젝트에서 vision encoder, MTP, full tokenizer 구현은 필수가 아니다. 먼저 **text backbone correctness**를 확보한다.

### 연계 규칙

- C++ pointer/array/lifetime/RAII 학습은 Qwen3.5 runtime의 weight/tensor/state ownership에 바로 적용한다.
- OS VM/thread/profiling은 runtime의 model loading, memory footprint, threading, inference 성능 분석에 연결한다.
- ML은 NN → RNN/LSTM/Seq2Seq → Attention → Transformer 순서로 진행하되, 이전 구조는 현대 모델 이해에 필요한 만큼만 학습한다.
- Transformer는 **NumPy로 single-head → decoder block → autoregressive inference/KV cache 순서로 직접 구현한 뒤** `llama2.c` 코드와 대응시킨다.
- `llama2.c`는 Transformer를 처음 배우는 교재가 아니라, 이미 이해한 inference 구조가 C에서 어떻게 구현되는지 확인하는 reference implementation으로 사용한다.
- Qwen3.5는 vanilla decoder와 `llama2.c`의 구조를 이해한 뒤, **GQA / Qwen-specific RoPE / hybrid layer / linear attention 등 차이점을 하나씩 추가**하는 방식으로 포팅한다.
- RL은 MDP/TD/PPO를 직접 한 번 구현해 보는 수준까지 진행하지만, Isaac 프로젝트의 최종 목표는 PPO가 아니라 **imitation/action model**이다.
- 로보틱스는 수식 완독보다 **robot state와 action model output이 실제 joint/control로 어떻게 연결되는지**를 이해하는 데 초점을 둔다.

## 3. 두 프로젝트의 최소 범위

### A. Robotics / Action Model Project (6학점)

```text
robot/environment
→ joint / DOF / coordinate / articulation
→ PD baseline
→ demonstration generation
→ Behavior Cloning
→ action chunk model
→ Isaac evaluation
```

최소 metric:

- success rate
- trajectory error
- RMSE
- max deviation
- settling time
- control effort
- disturbance robustness
- initial-state robustness

**성공 조건:** RL 성능을 최대화하는 것이 아니라, **PD → demonstration → BC → action chunk model**로 이어지는 pipeline을 직접 구성하고 정량 비교하면 성공.

### B. Minimal Qwen3.5 Runtime Capstone (6학점)

```text
Transformer inference 기초
→ NumPy single-head attention
→ NumPy tiny decoder
→ autoregressive decode / KV cache
→ llama2.c code path 추적
→ Qwen3.5 architecture 차이 분석
→ Qwen3.5 text weight loading
→ minimal C++ forward
→ HF correctness 검증
→ profiling
```

최소 구현 범위:

- NumPy single-head self-attention
- NumPy multi-head decoder block
- NumPy autoregressive generation
- NumPy KV cache
- token embedding
- RMSNorm
- Q/K/V projection
- RoPE
- causal self-attention
- multi-head / GQA
- FFN / SwiGLU
- residual connection
- LM head
- C++ autoregressive decode
- C++ KV cache
- Qwen3.5 text backbone에 필요한 Qwen-specific layer

제외 가능:

- vision encoder
- MTP
- training
- backward
- optimizer
- distributed inference
- full tokenizer 재구현
- aggressive SIMD optimization

correctness 검증 순서:

```text
NumPy tiny Transformer
→ llama2.c path 이해
→ Qwen3.5 1-layer output
→ several-layer output
→ full text-backbone hidden state
→ final logits
→ token-by-token generation
```

가능하면 동일 input에 대해 Hugging Face와 다음 intermediate를 비교한다.

```text
embedding
→ norm output
→ Q/K/V
→ attention output
→ FFN output
→ block output
→ final hidden state
→ logits
```

최소 metric:

- HF logits / hidden-state numerical difference
- tokens/sec
- time/token
- prompt processing time
- model load time
- peak RSS
- cycles / instructions / cache misses
- page faults / context switches

**우선순위:**

```text
correctness
→ reproducibility
→ profiling
→ optimization
```

최적화는 필수가 아니다.

시간이 남으면:

```text
cache locality / loop order
→ threading / affinity
→ SIMD
```

순서로 본다.

**성공 조건:** NumPy로 Transformer inference를 직접 설명/구현할 수 있고, `llama2.c`의 inference path를 이해한 뒤 **Qwen3.5 text backbone을 최소 C++ runtime에서 forward하여 Hugging Face reference와 numerical correctness를 검증**하면 성공.
