# 10-Week Self-Directed Semester

> **Modern C++ (3) + Operating Systems (3) + Machine Learning / Deep Learning (3) + RL / Action Models (3) + Unity Fixed-Wing Action Model Project (6) + Minimal Qwen3.5 Runtime Capstone (6)**  
> 핵심: **C++/OS/ML은 minimal Qwen3.5 C++ runtime 프로젝트에, ML/RL은 Unity fixed-wing action model 프로젝트에 직접 연결한다. Modern Robotics는 3D rigid-body state/action을 이해하기 위한 기초로 사용하고, 최종적으로 여러 agent가 LLM을 통해 자연어로 소통하도록 확장한다.**

### 교재 범위 원칙

- LearnCpp는 **필수 장 중심**으로 진행한다. pointer/reference/lifetime/RAII/move/STL을 우선하고, polymorphism과 exception 기본까지 학습한다.
- 복잡한 inheritance hierarchy, template metaprogramming, 디자인 패턴 암기는 하지 않는다.
- OSTEP은 **Process / Scheduling / Virtual Memory / Threads / Locks / Condition Variables**를 다룬다.
- ML은 고전 ML 전체를 훑지 않고 **NN → sequence model → attention → Transformer**로 이어지는 흐름만 다룬다.
- RNN/LSTM/Seq2Seq는 직접 깊게 구현하지 않고 **Transformer가 왜 등장했는지 이해하는 연결고리**로 본다.
- Transformer는 이론만 읽고 넘어가지 않고 **NumPy로 작은 decoder-only inference를 직접 구현**한다.
- NumPy scratch에서는 training/backprop/optimizer/tokenizer 학습까지 구현하지 않는다. **forward / autoregressive inference / KV cache 이해가 목표**다.
- RL은 MDP와 policy gradient를 학습하고 **작은 PPO를 직접 구현**한다. 작은 환경(CartPole 등)에서 학습이 되는 것을 확인하면 끝이며, 튜닝과 확장은 하지 않는다.
- Unity 프로젝트 자체는 PPO 중심으로 만들지 않는다. PPO는 continuous-control baseline으로 사용하고 최종 목표는 **imitation / temporal action model / hierarchy**다.
- Modern Robotics는 전통 로봇공학 전체를 완독하지 않는다. **configuration / rigid body / frame / rotation / transform / DOF / linear·angular velocity**를 핵심으로 한다.
- FK/Jacobian은 의미만 가볍게 보고, manipulator IK/dynamics/screw theory 심화는 제외한다.
- fixed-wing simulator는 실제 항공기 수준의 fidelity를 추구하지 않고 **thrust / lift / drag / control surface response를 단순화한 학습 환경**으로 만든다.
- 초기 observation은 vision이 아니라 **state-based observation**을 사용하고, waypoint와 다른 agent의 상태는 가능한 한 body-local frame으로 표현한다.
- low-level action은 `throttle / aileron / elevator / rudder`의 연속 제어로 제한한다.
- 여러 agent의 협력은 개별 flight policy가 안정적으로 동작한 뒤 추가한다.
- LLM은 저수준 조종값을 직접 출력하지 않고 **agent 간 communication, high-level subgoal, human command 해석과 상태 보고**를 담당한다.
- 자연어 통신은 every-step이 아니라 event-driven으로 사용하며, 실행 전 structured intent/subgoal로 변환한다.
- Hugging Face `transformers`는 별도로 학습하지 않고, Qwen3.5 구현 코드와 문서를 reference로 필요한 만큼만 참조한다.
- LLM 프로젝트는 **Transformer를 먼저 NumPy로 직접 구현한 뒤** `llama2.c`를 읽고, 그 다음 Qwen3.5 runtime을 구현한다.
- NumPy 단계는 single-head attention → multi-head decoder block → autoregressive generation → KV cache 순서로 구현한다.
- `llama2.c`는 Transformer를 처음 배우기 위한 코드가 아니라, NumPy에서 이해한 구조가 low-level C에서 어떻게 구현되는지 확인하는 reference implementation으로 사용한다.
- Qwen3.5 포팅은 `llama2.c`의 inference path까지 이해한 뒤 시작한다. vanilla decoder와의 차이를 하나씩 추가한다.
- Qwen3.5 프로젝트에서 vision encoder, MTP, full tokenizer 구현은 하지 않는다. **text backbone correctness**를 확보한다.

### 연계 규칙

- C++ pointer/array/lifetime/RAII 학습은 Qwen3.5 runtime의 weight/tensor/state ownership에 바로 적용한다.
- OS VM/thread/profiling은 runtime의 model loading, memory footprint, threading, inference 성능 분석에 연결한다.
- ML은 NN → RNN/LSTM/Seq2Seq → Attention → Transformer 순서로 진행하되, 이전 구조는 현대 모델 이해에 필요한 만큼만 학습한다.
- Transformer는 **NumPy로 single-head → decoder block → autoregressive inference/KV cache 순서로 직접 구현한 뒤** `llama2.c` 코드와 대응시킨다.
- `llama2.c`는 Transformer를 처음 배우는 교재가 아니라, 이미 이해한 inference 구조가 C에서 어떻게 구현되는지 확인하는 reference implementation으로 사용한다.
- Qwen3.5는 vanilla decoder와 `llama2.c`의 구조를 이해한 뒤, **GQA / Qwen-specific RoPE / hybrid layer / linear attention 등 차이점을 하나씩 추가**하는 방식으로 포팅한다.
- RL은 MDP/PPO를 직접 한 번 구현해 보는 수준까지 진행하지만, Unity 프로젝트의 최종 목표는 PPO가 아니라 **imitation / temporal action model / hierarchy**다.
- Modern Robotics는 **3D rigid body의 state/action interface와 coordinate transform을 이해하는 데 필요한 범위**만 학습한다.
- fixed-wing physics는 학습 가능한 수준까지만 구현하고, aerodynamic fidelity 자체를 프로젝트 목표로 삼지 않는다.
- 개별 agent의 low-level policy가 먼저 안정화된 뒤 multi-agent communication을 추가한다.
- LLM은 저수준 control loop와 분리하고 **event-driven high-level communication / subgoal generation**에만 사용한다.
- agent 간 자연어와 human-agent 자연어는 동일한 semantic interface를 공유하되, 실제 실행은 structured intent를 통해 action model로 전달한다.

## 3. 두 프로젝트의 최소 범위

### A. Fixed-Wing / Multi-Agent Action Model Project (6학점)

```text
fixed-wing environment
→ frame / rigid-body state / continuous control
→ scripted/autopilot baseline
→ PPO baseline
→ demonstration generation
→ Behavior Cloning
→ action chunk model
→ multi-agent environment
→ LLM language communication
→ Unity evaluation
```

최소 metric:

- waypoint / checkpoint success rate
- trajectory error
- heading / altitude error
- crash rate
- control effort / smoothness
- initial-state robustness
- terrain / waypoint variation robustness
- BC rollout success
- action-chunk rollout success
- multi-agent task success rate
- communication 없는 baseline 대비 성능
- messages / tokens per episode

**데이터 설계:** scripted/autopilot 데이터만 사용하면 행동 분포가 단순할 수 있으므로 초기 위치, heading, altitude, speed, waypoint를 랜덤화하고 필요하면 PPO rollout도 demonstration에 포함한다.

**Multi-agent 설계:** 2~4대 agent가 cooperative waypoint / formation / exploration task를 수행한다. 각 agent는 shared LLM의 별도 context를 사용하고, 자연어 message를 structured intent/subgoal로 변환한 뒤 기존 low-level action model을 실행한다.

**Human interface:** human command 역시 같은 language layer를 사용하여 team/agent subgoal로 변환하고, agent는 simulator state를 바탕으로 자연어 status report를 반환한다.

**성공 조건:** 최고 성능의 비행 제어나 대규모 MARL을 만드는 것이 아니라, **continuous control → PPO → demonstration → BC → action chunk → language-mediated multi-agent coordination** pipeline을 직접 구성하고 정량 비교하면 성공.

### B. Minimal Qwen3.5 Runtime Capstone (6학점)

```text
Transformer inference 기초
→ NumPy single-head attention
→ NumPy tiny decoder
→ autoregressive decode / KV cache
→ llama2.c code path 추적
→ Qwen3.5 architecture 차이 분석
→ Qwen3.5 text weight loading
→ minimal C++ forward
→ HF correctness 검증
→ profiling
```

구현 범위:

- NumPy single-head self-attention
- NumPy multi-head decoder block
- NumPy autoregressive generation
- NumPy KV cache
- token embedding
- RMSNorm
- Q/K/V projection
- RoPE
- causal self-attention
- multi-head / GQA
- FFN / SwiGLU
- residual connection
- LM head
- C++ autoregressive decode
- C++ KV cache
- Qwen3.5 text backbone에 필요한 Qwen-specific layer

제외:

- vision encoder
- MTP
- training
- backward
- optimizer
- distributed inference
- full tokenizer 재구현
- SIMD optimization

correctness 검증 순서:

```text
NumPy tiny Transformer
→ llama2.c path 이해
→ Qwen3.5 1-layer output
→ several-layer output
→ full text-backbone hidden state
→ final logits
→ token-by-token generation
```

동일 input에 대해 Hugging Face와 다음 intermediate를 비교한다.

```text
embedding
→ norm output
→ Q/K/V
→ attention output
→ FFN output
→ block output
→ final hidden state
→ logits
```

최소 metric:

- HF logits / hidden-state numerical difference
- tokens/sec
- time/token
- prompt processing time
- model load time
- peak RSS
- cycles / instructions / cache misses
- page faults / context switches

**우선순위:**

```text
correctness
→ reproducibility
→ profiling
→ optimization
```

최적화는 마지막 순서이며 cache locality / loop order, threading / affinity 중 1개까지만 한다.

**성공 조건:** NumPy로 Transformer inference를 직접 설명/구현할 수 있고, `llama2.c`의 inference path를 이해한 뒤 **Qwen3.5 text backbone을 최소 C++ runtime에서 forward하여 Hugging Face reference와 numerical correctness를 검증**하면 성공.
