# 16-Week Self-Directed Semester — Full Curriculum

## Semester structure

| Course | Credits | Main goal |
|---|---:|---|
| C++ | 3 | Write and debug nontrivial modern C++ programs; understand memory, RAII, STL, move semantics, templates |
| Operating Systems | 3 | Understand processes, virtual memory, concurrency, file systems, and system calls |
| Machine Learning & Mathematical Foundations | 3 | Fill probability/linear-algebra gaps and reach paper-reading-level ML foundations |
| Reinforcement Learning | 3 | Understand MDP → value methods → function approximation → policy gradients → PPO |
| Robotics / Isaac Lab | 6 | Build and train a custom robot-control environment, ending in a gimbal PPO project |
| **Total** | **18** | |

The courses are meant to run **in parallel**, not sequentially.

## C++ priorities

For robotics/simulator code, prioritize:
- references, pointers, const, value categories
- scope and object lifetime
- structs/classes and constructors
- RAII and ownership
- std::vector and containers
- iterators and generic algorithms
- inheritance / virtual functions
- templates at library-reading level
- headers, translation units, compiler/linker errors
- debugging with warnings, breakpoints, and call stack

The finish line is being able to read and modify robotics/C++ library code without syntax and ownership semantics constantly blocking you.

# 3. Machine Learning & Mathematical Foundations — 3 credits

## Main reference
**Kevin P. Murphy, _Probabilistic Machine Learning: An Introduction_ (2022)**

This remains the only required ML textbook. The course is now **implementation-first, theory-on-demand**:
1. build an MLP from scratch once;
2. reproduce it in PyTorch;
3. learn the probability/statistics/linear algebra that explain it;
4. move earlier into CNNs, attention, Transformers, and ViT.

## Weekly curriculum

| Week | Main topic | PML sections | Output |
|---|---|---|---|
| **1** | MLP from scratch | skim **Ch.13.1–13.3** as needed | NumPy MLP: Linear → ReLU → output, forward, loss, manual backward, SGD; numerical gradient check |
| **2** | Same MLP in PyTorch | **Ch.13.3–13.4** | tensors, autograd, `nn.Module`, optimizer, minibatches; distinguish backprop from parameter update |
| **3** | Training dynamics | **Ch.13.4–13.5** + selected **Ch.8** | SGD/Adam, learning rate, initialization, vanishing/exploding gradients, residuals, regularization, validation |
| **4** | Probability foundations | **Ch.2.1–2.6** | random variables, PMF/PDF/CDF, expectation, variance, independence, Bayes, Bernoulli/categorical/Gaussian |
| **5** | Multivariate probability | **Ch.3.1–3.3, 3.5** | covariance, correlation, independent vs uncorrelated, multivariate Gaussian, covariance geometry |
| **6** | Statistics / likelihood | **Ch.4.1–4.5** | MLE, ERM, surrogate losses, regularization, validation/CV; MSE↔Gaussian, CE↔classification likelihood |
| **7** | Bayesian + information theory | **Ch.4.6–4.7**, **Ch.6.1–6.3**, selected **Ch.5.1** | MAP, prior/posterior, Bayesian vs frequentist, bias-variance, entropy, cross-entropy, KL, ROC/PR |
| **8** | Linear algebra for modern ML | **Ch.7.1–7.5, 7.7–7.8** | basis, rank, projection, eigen, symmetric matrices, SVD, pseudoinverse, gradient/Jacobian/Hessian |

| **10** | CNN fundamentals | **Ch.14.1–14.3** | convolution, channels, receptive fields, pooling, normalization; small CNN |
| **11** | Modern CNNs / residual learning | selected **Ch.14** | ResNet ideas, residual connections, transfer/fine-tuning intuition |

## Week 1 scope
Week 1 is deliberately only one week. Implement enough to demystify:
`forward → loss → backward → gradients → parameter update`.

Do **not** build a general autograd engine, optimizer library, or convolution backward from scratch.

## Mathematics that remains mandatory
Probability/statistics:
- random variables, expectation/variance
- covariance/correlation
- Bayes, Gaussian/multivariate Gaussian
- likelihood/MLE/MAP
- entropy/cross-entropy/KL

Linear algebra:
- basis/rank, projection
- eigenvalues/eigenvectors
- symmetric matrices, SVD, pseudoinverse
- PCA

Calculus/optimization:
- gradient, Jacobian, Hessian intuition
- chain rule
- SGD, learning rate, momentum/Adam
- convex vs nonconvex intuition

## Practical checkpoints
- **Week 1:** NumPy MLP + finite-difference gradient check
- **Week 2:** same model in PyTorch
- **Week 3:** learning-rate / optimizer / initialization / regularization experiments
- **Weeks 4–7:** probability/statistics exercises tied to actual losses
- **Weeks 8–9:** EVD/SVD/PCA in NumPy
- **Weeks 10–11:** train a small CNN
- **Weeks 12–14:** implement self-attention and trace tensor shapes
- **Weeks 15–16:** understand and dissect a minimal ViT-style model

VLA remains out of scope.

## Milestones
**End Week 3:** manually implement an MLP, use PyTorch correctly, explain backprop vs optimizer update.

**End Week 7:** explain PMF/PDF, expectation/variance/covariance, likelihood/MLE/MAP, entropy/CE/KL, and probabilistic interpretations of common losses.

**End Week 9:** explain eigen/SVD/PCA and implement PCA.

**Reinforcement Learning: An Introduction, 2nd Edition — Sutton & Barto**

- **Schulman et al., Proximal Policy Optimization Algorithms**

## RL coding progression

- Weeks 1–6: tiny NumPy/Gymnasium examples if useful
- Weeks 8–12: small PyTorch policy/value networks
- Weeks 13–16: read and modify RSL-RL PPO configs rather than reimplementing an entire production PPO stack

## RL endpoint

You should be able to answer:

- Why do we need \(V\) and \(Q\)?
- What is bootstrapping?
- Why does actor-critic use a critic?
- What is an advantage?
- Why does PPO use a probability ratio?
- What exactly does clipping prevent?
- What data are collected during a rollout?
- Which parts of RSL-RL correspond to the equations?

# 5. Robotics / Isaac Lab — 6 credits

## Main goal
Build enough robotics/control intuition to create, debug, train, and evaluate a custom Isaac Lab environment without treating either the simulator or PPO as a black box.

Final project: **2-axis gimbal stabilization**, comparing a classical PD/PID baseline with PPO under disturbance, noise, delay, and parameter variation.

## References
### Robotics theory
**Modern Robotics — Lynch & Park**
- Ch.3 Rigid-Body Motions
- Ch.4 Forward Kinematics
- selected Ch.5 Velocity Kinematics and Statics
- selected Ch.11 Robot Control

### Simulator / RL framework
**Isaac Lab 3.0 docs + locally installed examples**

Prefer:
1. local known-good task source
2. local API signatures/source
3. matching release-3.0 docs
4. generic web examples only as secondary references

## Core workflow
`known-good task → inspect → modify → direct articulation control → PD/PID → custom DirectRLEnv → validate without RL → PPO → randomization/noise → evaluation`

## Weekly curriculum

| Week | Topic | Required implementation |
|---|---|---|
| **1** | Known-good workflow | Train/play Cartpole; locate env config, task code, agent config; trace `obs → policy → action → env`; verify external-project workflow |
| **2** | Frames and rotations | Learn selected Modern Robotics Ch.3; inspect world/body poses in Isaac; manually alter orientation and verify state |
| **3** | Quaternion + articulation API | Read joint pos/vel, root pose/angular velocity; command a simple joint; connect rotation theory to actual tensors |
| **4** | Joints, FK, actuator interfaces | Build/manipulate a simple 1–2 DOF mechanism; test position/velocity/torque targets; verify axes and limits |
| **5** | Velocity/Jacobian intuition | Use only enough Ch.5 to understand local motion; relate joint velocity to end-frame/angular motion |
| **6** | Classical feedback control | Implement P → PD → optional PID gimbal stabilization; record baseline error under deterministic disturbances |
| **7** | Read a known-good Direct task | Dissect config, `_setup_scene`, action hooks, obs, rewards, dones, reset; copy and modify one small element |
| **8** | Build custom `DirectRLEnv` | Create gimbal env skeleton; implement scene/action/obs/reward/done/reset; start with one env |
| **9** | **BUFFER / INTEGRATION** | No new theory. Fix asset/import/API/version problems; validate axes/limits/actuators; make train/play/random-agent repeatable |
| **10** | Validate env before RL | Run **zero agent → random agent → scripted/manual actions**; sanity-check obs, action signs/scales, rewards, dones, resets; then scale to parallel envs |
| **11** | Batching + PPO connection | Verify batched tensors/selective reset; connect RSL-RL PPO only after checks pass; do a short smoke training run |
| **12** | Reward shaping / first useful PPO | Tune orientation error, angular velocity, action/action-change penalties; obtain first visibly stabilizing policy |
| **13** | Disturbance/randomization | Randomize initial state, disturbance magnitude/direction, motor/physics parameters |
| **14** | Observation realism | Add noise, action/observation delay, optional previous action; test partial/noisy observations |
| **15** | Evaluation / ablation | PD/PID vs PPO; easy/hard disturbances; with/without randomization; reward ablations; measure error/control effort |
| **16** | Final integration | Clean code/configs; robustness evaluation; plots/video; final report with failures and lessons |

## Weeks 2–6 rule
Theory must immediately touch the simulator:
`learn concept → inspect Isaac state → manipulate it → predict result → verify`.

Do not study long derivations detached from the project.

## Direct environment hooks
By end of Week 8, understand:
`_setup_scene()`, `_pre_physics_step(actions)`, `_apply_action()`, `_get_observations()`, `_get_rewards()`, `_get_dones()`, `_reset_idx(env_ids)`.

Also:
`EnvCfg = design/configuration`, `Env = runtime behavior`.

## Mandatory pre-PPO validation gate
Before any serious PPO run:

1. **Zero-action test** — stable sim, finite observations, valid resets.
2. **Random-action test** — intended joints move, action signs/scales make sense, no NaN/Inf.
3. **Scripted-action test** — known positive/negative commands create predicted motion and reward changes.
4. **Done/reset test** — only intended envs reset; buffers/state are valid.
5. **Parallel-env test** — shapes, `env_origins`, cloning, selective resets all correct.

Only then treat poor training as an RL problem.

## Initial gimbal specification
### Observation
Start small:
- orientation error
- angular velocity
- joint pos/vel if needed
- previous action only later if useful

### Action
Choose one interface first:
- torque target, **or**
- velocity target, **or**
- position target

Do not change action semantics while debugging reward/training.

### Reward
Start interpretable:
- orientation error penalty
- angular velocity penalty
- action magnitude / action-change penalty

Log terms separately.

## Classical baseline
PD/PID is mandatory. Compare against PPO on the same disturbances and record:
- mean error
- high-percentile/max error
- settling behavior
- control effort
- failure cases

## PPO mapping
Understand:
`observations → actor → action → actuator → rollout → rewards/dones → returns/advantages → PPO update`.

Know what config values mean for:
- actor/critic size
- rollout horizon
- gamma
- GAE lambda
- learning rate
- epochs/minibatches
- PPO clipping
- entropy coefficient
- value-loss coefficient

The RL course provides the theory; this course focuses on mapping that theory into Isaac/RSL-RL.

## Final deliverables
- custom gimbal env
- PD/PID baseline
- PPO config
- train/play/eval scripts
- zero/random/scripted sanity tests
- robustness experiments
- final report/video

## End-of-semester target
Be able to repeat:
`asset/articulation → inspect state → choose action interface → scripted control → classical baseline → DirectRLEnv → validation → parallel sim → PPO → randomization → evaluation`.
