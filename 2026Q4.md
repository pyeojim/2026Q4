## C++ priorities

For robotics/simulator code, prioritize:
- references, pointers, const, value categories
- scope and object lifetime
- structs/classes and constructors
- RAII and ownership
- std::vector and containers
- iterators and generic algorithms
- inheritance / virtual functions
- templates at library-reading level
- headers, translation units, compiler/linker errors
- debugging with warnings, breakpoints, and call stack

The finish line is being able to read and modify robotics/C++ library code without syntax and ownership semantics constantly blocking you.

# 3. Deep Learning & Reinforcement Learning for Robotics — 6 credits

## Course goal

This course merges the previous ML and RL tracks into one coherent sequence.

The objective is not to survey every classical ML/RL algorithm. The objective is to build the foundations that are most likely to remain useful for:

- deep learning
- robot learning
- reinforcement learning
- vision
- Transformers / ViT
- later VLM / VLA study

The course is deliberately **implementation-first, theory-on-demand**:

```text
MLP from scratch
→ PyTorch / optimization
→ probability / statistics / information theory
→ linear algebra / PCA
→ RL fundamentals
→ function approximation
→ policy gradients / actor-critic
→ GAE / PPO
→ CNN compressed module
→ attention / Transformer
→ ViT
→ PPO implementation / integration
```

This removes overlap between the old ML and RL courses and compresses topics that are useful but do not need entire weeks.

## What was deliberately compressed

### CNN
CNN is **not removed**.

It is compressed from two weeks to roughly one week because the important long-term concepts are:

- local connectivity
- weight sharing
- channels
- stride / padding
- receptive field
- pooling
- residual connections
- CNN inductive bias

You do **not** need:

- long architecture-history study
- manual convolution backward derivations
- separate deep dives into AlexNet/VGG/etc.
- multiple weeks of CNN implementation

One solid implementation plus a ResNet-level conceptual understanding is enough for now.

### PCA
PCA stays, but only as a compact application of:

```text
covariance
→ eigenvectors / SVD
→ principal directions
→ dimensionality reduction
```

It does not need a full week of independent treatment.

### Bayesian / frequentist statistics
Keep:

- likelihood
- MLE
- MAP
- prior/posterior intuition
- confidence vs credible interval intuition
- bias-variance

Compress or defer:

- long conjugate-prior derivations
- detailed asymptotic statistics
- bootstrap details
- hypothesis-testing machinery

### Classical RL
The old RL curriculum spent separate weeks on DP, MC, n-step, and off-policy instability.

These are now compressed.

Keep:

- Bellman equations
- policy evaluation/improvement
- MC vs TD distinction
- SARSA / Q-learning
- bootstrapping
- n-step intuition
- function approximation
- deadly-triad intuition

Do not spend entire weeks on each historical step.

### Off-policy instability
Know the idea:

```text
function approximation
+ bootstrapping
+ off-policy learning
= possible instability
```

Do not spend a separate week proving or cataloging failure modes.

Minimum scratch implementation:

```text

```

Do not build a general autograd engine.

- sample distributions


# 5. Robotics / Isaac Lab — 6 credits

## Main goal
Build enough robotics/control intuition to create, debug, train, and evaluate a custom Isaac Lab environment without treating either the simulator or PPO as a black box.

Final project: **2-axis gimbal stabilization**, comparing a classical PD/PID baseline with PPO under disturbance, noise, delay, and parameter variation.

## Weeks 2–6 rule
Theory must immediately touch the simulator:
`learn concept → inspect Isaac state → manipulate it → predict result → verify`.

Do not study long derivations detached from the project.

## Direct environment hooks
By end of Week 8, understand:
`_setup_scene()`, `_pre_physics_step(actions)`, `_apply_action()`, `_get_observations()`, `_get_rewards()`, `_get_dones()`, `_reset_idx(env_ids)`.

Also:
`EnvCfg = design/configuration`, `Env = runtime behavior`.

## Mandatory pre-PPO validation gate
Before any serious PPO run:

1. **Zero-action test** — stable sim, finite observations, valid resets.
2. **Random-action test** — intended joints move, action signs/scales make sense, no NaN/Inf.
3. **Scripted-action test** — known positive/negative commands create predicted motion and reward changes.
4. **Done/reset test** — only intended envs reset; buffers/state are valid.
5. **Parallel-env test** — shapes, `env_origins`, cloning, selective resets all correct.

Only then treat poor training as an RL problem.

## Initial gimbal specification
### Observation
Start small:
- orientation error
- angular velocity
- joint pos/vel if needed
- previous action only later if useful

### Action
Choose one interface first:
- torque target, **or**
- velocity target, **or**
- position target

Do not change action semantics while debugging reward/training.

### Reward
Start interpretable:
- orientation error penalty
- angular velocity penalty
- action magnitude / action-change penalty

Log terms separately.

## Classical baseline
PD/PID is mandatory. Compare against PPO on the same disturbances and record:
- mean error
- high-percentile/max error
- settling behavior
- control effort
- failure cases

## PPO mapping
Understand:
`observations → actor → action → actuator → rollout → rewards/dones → returns/advantages → PPO update`.

Know what config values mean for:
- actor/critic size
- rollout horizon
- gamma
- GAE lambda
- learning rate
- epochs/minibatches
- PPO clipping
- entropy coefficient
- value-loss coefficient

The RL course provides the theory; this course focuses on mapping that theory into Isaac/RSL-RL.
