# 16-Week Self-Directed Semester
## Intelligent Robot Software / Embodied Manipulation

> **최종 목표**
>
> 시각·언어·로봇 상태를 바탕으로 상황을 이해하고, 적절한 manipulation action을 생성하며,
> 이를 실제 로봇 시스템에서 안정적으로 실행할 수 있는 소프트웨어를 설계한다.
>
> 핵심은 **“잘 집는 기계” 자체보다 “무엇을 어떻게 집어야 하는지 판단하고 실행하는 로봇 소프트웨어”**다.
> Isaac Sim / Isaac Lab은 학습 목표가 아니라 **가상 실험실**로 사용한다.

### 핵심

## Reinforcement Learning — Learning to Act

### 목표
물리적인 제어 문제를 sequential decision-making problem으로 바꾸고 policy를 학습시킨다.

### 핵심
- MDP
- return / discount
- value / Q
- Bellman equation
- MC / TD
- policy gradient
- actor-critic
- advantage / GAE
- PPO clipping
- entropy

### 핵심 능력

```text

control input  → action
desired behavior → reward
success/failure → termination
```

# 5. Vision / VLM의 위치

Vision과 VLM은 처음부터 붙이지 않는다.

```text
Stage 1
GT robot/object state
→ action model

Stage 2
camera
→ explicit object / gripper state
→ action model

Stage 3
camera
→ vision latent
→ action model

Stage 4
vision + language + proprioception
→ task representation
→ action model
```

역할 분리:

```text
VLM
→ 무엇을 해야 하는가?
→ 어떤 물체가 목표인가?

Vision / Tracker
→ 지금 물체와 gripper가 어디 있는가?

Action Model
→ 어떻게 움직일 것인가?

Controller
→ 실제로 실행
```

이번 학기에는 pretrained VLM을 직접 학습하는 것을 필수 목표로 두지 않는다.

# 7. 평가 기준

## Robotics
- state를 직접 정의했는가
- pose / kinematics를 설명할 수 있는가
- dynamics와 actuator 관계를 이해하는가
- controller를 직접 설계했는가
- metric을 정의하고 비교했는가

## Robot Learning
- control problem을 MDP로 정의할 수 있는가
- observation / action / reward 설계 이유를 설명할 수 있는가
- PPO 데이터 흐름을 설명할 수 있는가
- trajectory dataset과 action model을 설계할 수 있는가
- rollout failure를 분석할 수 있는가

## Systems
- inference latency와 control latency를 구분할 수 있는가
- process / thread / synchronization을 선택할 수 있는가
- blocking이 control loop에 미치는 영향을 설명할 수 있는가

## ML
- loss가 무엇을 최적화하는지 설명할 수 있는가
- representation과 prediction을 구분할 수 있는가
- MLP / Transformer 선택 이유를 설명할 수 있는가

# 8. 진행 원칙

1. Isaac API 사용법과 로보틱스 학습목표를 구분한다.
2. **모델링 → baseline → learning → 비교** 순서를 지킨다.
3. 처음부터 vision/VLM을 붙이지 않는다.
4. GT state는 초기 curriculum stage로 사용한다.
5. RL만 고집하지 않고 문제에 맞게 BC/action model을 사용한다.
6. perception / action model / controller / systems failure를 분리해서 분석한다.
7. 최종 기본 구조는 **vision + proprioception**이다.
8. 목표는 특정 물체를 잘 집는 것이 아니라 **새로운 상황에 대응 가능한 manipulation software**다.
